## Purpose

Turn client engagements into compelling, credible case studies that demonstrate the FDE model in action. Not marketing fluff — documented proof that the system works.

**Trigger:** A client engagement has completed (or reached a measurable milestone). Time to document and publish.

---

## The Case Study Framework

### Principle: Specificity = Credibility

> "Vague case studies sound like marketing. Specific case studies sound like proof."

---

## Section 1: Before (The Pain)

### 1.1 Client Context

**Template:**
```
[Company] is a [industry] company with [team size] sales reps,
managing [portfolio size / deal volume].

Their challenge: [specific, quantified problem]
```

**Example:**
```
Acme Corp is a B2B software company with 8 sales reps,
managing a €5M pipeline.

Their challenge: Reps spent 12 hours/week on CRM updates
and manual follow-ups. 3 deals were lost in Q2 due to
forgotten follow-ups.
```

### 1.2 The Cost of Inaction

**Template:**
```
The cost of doing nothing:
- Time lost: [X] hours/week = €[X/year]
- Deals lost: [X] in [timeframe]
- Opportunity cost: [specific, quantified]
```

---

## Section 2: During (The Engagement)

### 2.1 The Audit Findings

**Template:**
```
During the AI Sales Process Audit, we identified:

1. [Finding 1]: [specific issue] → [impact]
2. [Finding 2]: [specific issue] → [impact]
3. [Finding 3]: [specific issue] → [impact]

Priority: [which finding to address first and why]
```

### 2.2 The Build

**Template:**
```
Over [X weeks], we built:

[System 1]: [What it does]
- Before: [manual process]
- After: [automated process]
- Tools used: [specific tools]

[System 2]: [What it does]
- Before: [manual process]
- After: [automated process]
- Tools used: [specific tools]
```

**Rule:** Name the actual tools. "n8n" not "automation platform." Specificity builds credibility.

### 2.3 The Challenges

**Template:**
```
What didn't go smoothly:
- [Challenge 1]: [What happened] → [How we fixed it]
- [Challenge 2]: [What happened] → [How we fixed it]

This is normal. Every build has surprises. The FDE model
accounts for this — I'm there to adapt, not just deliver a spec.
```

**Critical:** Include the challenges. Perfect case studies sound fake.

## Section 3: After (The Results)

### 3.1 Quantified Outcomes

**Template:**
```
Results after [timeframe]:

| Metric | Before | After | Change |
|--------|--------|-------|--------|
| [Metric 1] | [X] | [Y] | [Z%] |
| [Metric 2] | [X] | [Y] | [Z%] |
| [Metric 3] | [X] | [Y] | [Z%] |

Time to value: [X weeks]
ROI: [X]x investment in [timeframe]
```

**Rule:** Use client's actual numbers. If they won't share, use ranges ("saved 8–12 hours/week").

### 3.2 Client Quote

**Template:**
```
"[Specific quote about the outcome, not generic praise.]"

— [Name], [Title], [Company]
```

**Good:** "The automated nurture sequence saved our team 10 hours a week. We stopped losing deals to forgotten follow-ups."

**Bad:** "Colin was great to work with. Highly recommend."

### 3.3 What Happened Next

**Template:**
```
Since the initial build:
- [Update 1: system evolution]
- [Update 2: new automation added]
- [Update 3: team adoption rate]
```

## Case Study Formats

### Format A: Long-Form (1,500–2,000 words)
- Full narrative: Before → During → After → Lesson
- Published: Blog post, newsletter feature
- SEO value: High

### Format B: Short-Form (300–500 words)
- Problem → Solution → Result
- Published: LinkedIn post, email snippet
- Shareability: High

### Format C: Visual (1-page PDF)
- Infographic-style: stats, quote, CTA
- Published: Website download, sales collateral
- Conversion: High

### Format D: Video (2–3 minutes)
- Screen recording of system + voiceover
- Published: YouTube, LinkedIn, website
- Engagement: High

## Client Permission Protocol

**Before publishing any case study:**

1. **Send draft to client** for approval
2. **Anonymize if requested** ("B2B software company" instead of "Acme Corp")
3. **Get written approval** (email reply is fine)
4. **Offer to share traffic stats** (builds relationship)
5. **Include link** in the published case study (backlink for their SEO)

**Template email:**
```
Hi [Name],

I wrote up a case study about our work together. Here's the draft:
[link]

Happy to anonymize if you prefer ("B2B software company" vs "Acme").

Let me know if you're okay with me publishing this, or if you'd
like any changes.

Colin
```

## Case Study Checklist

Before publishing, verify:

- [ ] Client has approved (or anonymized)
- [ ] All numbers are real or clearly marked as estimated
- [ ] No confidential information exposed
- [ ] Quote is specific, not generic
- [ ] Challenges are included (not just wins)
- [ ] Tools are named specifically
- [ ] CTA is clear and correct
- [ ] Currency is €
- [ ] Links work (Calendly, website, related posts)
- [ ] Images/screenshots have alt text

## Anti-Patterns

### Anti-Pattern 1: The Fluff Case Study
**Symptom:** Vague, no numbers, generic praise.
**Fix:** Include specific metrics. Name tools. Quote real people.

### Anti-Pattern 2: The Perfect Story
**Symptom:** Everything went smoothly. No challenges.
**Fix:** Include 2–3 challenges and how they were solved. Real projects have friction.

### Anti-Pattern 3: The Ghost Client
**Symptom:** No client name, no quote, no photo.
**Fix:** Get permission. If they won't allow naming, anonymize but keep the quote ("Sales Director, B2B software company").

### Anti-Pattern 4: The Self-Promotion Bomb
**Symptom:** Case study is 80% about Colin, 20% about client.
**Fix:** 60% client, 30% process, 10% Colin. The client is the hero.
